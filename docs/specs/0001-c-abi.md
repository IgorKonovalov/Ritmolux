# Spec — C ABI (foobar plugin seam)

> **Subsystem:** The versioned `extern "C"` surface the foobar2000 C++ shim links against — the one seam between a frontend and `core`.
> **Source:** `core-cabi/src/lib.rs` (definitions), `core-cabi/include/lmv_core.h` (C mirror the shim compiles against)
> **Reconciled-through:** Plan 0014 (surface at **v4**; reconciled 2026-07-25). **Paths re-pointed at
> Plan 0061's close (2026-08-08):** [ADR-0072](../adrs/0072-the-c-abi-ships-from-its-own-crate.md) moved
> the definitions and the header out of `core/` into the `lmv-core-cabi` crate. **The surface itself did
> not move** — same twelve functions, `LMV_ABI_VERSION` still `4`, ADR-0003's rule untouched; only where
> it compiles changed. Note that `lmv-core-cabi` sits outside the workspace `default-members`, so the
> conformance suite below runs under `--workspace` or `-p lmv-core-cabi` and **not** under a bare
> `cargo nextest run`.
> **Governing ADRs:** [0003](../adrs/0003-c-abi-v1-surface.md) (v1 surface + the freeze rationale), extended by [0006](../adrs/0006-c-abi-v2-preset-loading.md) (v2), [0008](../adrs/0008-c-abi-v3-diagnostics.md) (v3), [0013](../adrs/0013-c-abi-v4-render-dt.md) (v4); [0001](../adrs/0001-rust-core-wgpu-cabi-foobar-shim.md) (the seam exists)

## Invariants

- The current surface (`LMV_ABI_VERSION = 4`) MUST be exactly these **twelve** functions and no
  others: `lmv_abi_version`, `lmv_create`, `lmv_free`, `lmv_push_samples`, `lmv_attach_window`,
  `lmv_render`, `lmv_render_dt`, `lmv_resize`, `lmv_cycle_scene`, `lmv_load_presets`,
  `lmv_set_debug`, `lmv_get_metrics`. Each addition since v1 carries its own ADR: `lmv_load_presets`
  (v2, ADR-0006), `lmv_set_debug` + `lmv_get_metrics` + `LmvMetrics` (v3, ADR-0008), `lmv_render_dt`
  (v4, ADR-0013). (`core-cabi/src/lib.rs`)
- `LMV_ABI_VERSION` MUST change **only** when the shape of the `extern "C"` surface changes
  (a signature, a function, an error code) — never as a side effect of an application version
  bump. It is a separate axis from the app version (ADR-0005). (ADR-0003)
- The C header `core-cabi/include/lmv_core.h` MUST match `core-cabi/src/lib.rs` signature-for-signature,
  **including the `LMV_ABI_VERSION` literal and the `LmvMetrics` field layout**; the shim compiles
  against the header separately from the Rust crate, so a drift is a link/runtime error, not a
  compile error. (ADR-0003)
- Every pointer crossing the boundary MUST be validated where it enters the core (null checks,
  handle validity); the hot path downstream trusts it. Validate at the boundary, trust inside.
  (CLAUDE.md non-negotiables)
- A panic MUST NOT cross the boundary: every entry point catches unwinds and maps them to
  `LMV_ERR_PANIC` (`-5`) rather than unwinding into C++. (`core-cabi/src/lib.rs` module doc)
- `lmv_push_samples` MUST NOT allocate, block, lock a contended mutex, log, or do file I/O —
  it runs on the caller's audio-delivery thread. It hands samples to the ring and returns.
  (CLAUDE.md; see [0002-ring-determinism](0002-ring-determinism.md))
- The threading contract MUST hold in both directions: `lmv_push_samples` from at most one
  thread (the host's audio/visualisation thread), every other call from at most one thread (the
  host's UI/render thread), and never concurrently with `lmv_create`/`lmv_free` on the same
  handle. The two roles meet only at the lock-free ring. (`core-cabi/src/lib.rs`, mirrored in the header)
- **No allocation crosses the boundary.** `LmvMetrics` is caller-allocated plain data; it leads
  with `struct_size` + `abi_version` so later fields can append **without** an ABI bump
  (forward-extensible by size). (ADR-0008)
- Widening the surface (a thirteenth function, a changed signature) is an ADR-worthy event, not a
  casual edit. The seam stays minimal: create / free / push / attach / render / resize /
  cycle-scene / load-presets / debug / metrics. (ADR-0001, ADR-0003)

## Scenarios

- WHEN the C++ shim calls `lmv_abi_version()` THEN it returns `4`, letting the shim refuse a
  core whose ABI it was not built against (it compares against the header's `LMV_ABI_VERSION`).
- WHEN `lmv_create` succeeds THEN it returns an opaque non-null handle that every other call
  (except `lmv_abi_version`) takes as its first argument; WHEN it fails THEN it returns null
  and no handle is leaked.
- WHEN `lmv_push_samples` is called with a valid handle and a sample buffer THEN the samples
  are copied into the lock-free ring and the call returns immediately, without touching the
  render path.
- WHEN `lmv_push_samples` is called with a null handle or null buffer THEN it is rejected at
  the boundary with `LMV_ERR_INVALID_ARG` (no deref of the invalid pointer), not passed inward.
- WHEN `lmv_render_dt(handle, dt)` is called THEN the frame advances by the host's **real**
  elapsed seconds, so animation is frame-rate independent; WHEN the legacy `lmv_render(handle)`
  is called THEN it is exactly `lmv_render_dt(handle, 1.0/60.0)` — the fixed-step wrapper kept
  for v1-era callers (ADR-0013).
- WHEN a render call is made before `lmv_attach_window` THEN it returns `LMV_ERR_NO_WINDOW`
  rather than rendering or panicking.
- WHEN `lmv_load_presets` is called **before** a window is attached THEN the parsed set is held
  pending and installed as soon as `lmv_attach_window` creates the renderer, and the call still
  reports the loaded count (ADR-0006).
- WHEN `lmv_get_metrics` is called with a caller-allocated `LmvMetrics` THEN the core stamps
  `struct_size` with the byte count it actually wrote and `abi_version` with `LMV_ABI_VERSION`,
  so a host built against an older header reads a prefix rather than garbage (ADR-0008).
- WHEN `lmv_free` is called on a handle THEN all core resources for that handle are released
  and the handle MUST NOT be used again.
- WHEN the `extern "C"` surface must change shape THEN `LMV_ABI_VERSION` is bumped and a new
  ADR records the addition — the app version (ADR-0005) is untouched by this.

## Known gaps / honest nulls

- **Rust-side FFI coverage exists; the C++ shim is still untested in CI.** `core/tests/ffi.rs`
  drives `lmv_create` → `lmv_load_presets` → `lmv_render_dt` / `lmv_set_debug` /
  `lmv_get_metrics` → `lmv_free` across the boundary, including the null-argument error paths and
  the version handshake. What remains uncovered is the **C++ side**: `plugin-foobar/` is not
  built in CI (it needs the foobar SDK + MSVC), so header-vs-`ffi.rs` drift is caught only by a
  local plugin build.
- **The header is a hand-maintained mirror.** Nothing mechanically checks
  `core-cabi/include/lmv_core.h` against `core-cabi/src/lib.rs` (no `cbindgen`, per ADR-0003's
  keep-it-small posture). The invariant above is enforced by review, not by a gate.
- This spec covers the *contract shape and boundary discipline*, not the per-call payload
  semantics of rendering (frame timing, surface format) — those live with the render/scene
  subsystem and the wgpu layer.
