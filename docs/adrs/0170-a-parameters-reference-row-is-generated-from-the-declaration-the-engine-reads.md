# ADR-0170 — A parameter's reference row is generated from the declaration the engine reads

> **Status:** accepted 2026-09-06 (Plan 0156)
> **Date:** 2026-09-06
> **Related plan(s):** [0156](../plans/done/0156-the-site-becomes-the-reference.md) Phase 7
> **Extends:** [0017](0017-preset-author-skill-lane.md) (the roster is the lane's catalogue),
> [0163](0163-a-long-document-carries-a-generated-contents-block.md) (a generated block is never hand-edited)

## Context

The preset format is the largest public surface of the application, and its reference is
`presets/README.md`. That file is complete — a test, `every_declared_param_is_documented_in_the_presets_readme`,
holds it to naming every parameter the engine declares — and it is 268 KB of *essays*: a section on
attractor depth, a section on shaped marks, a section on why a rate integrates a phase. Each system's
own parameters appear once, as a single table row listing names and nothing else:

```
| `fragment_field` | `warp` `field_speed` `fold_speed` `hue` `zoom` `glow` `flash` · `pan_x` ... |
```

A reader who wants to know what `flash` does, what its default is and what range reads has to
search the essays, and for a parameter with no essay — `flash`, `glow`, most of the palette block —
the answer is in `core/src/render/scenes/fragment_field.rs` and nowhere else. Counted on the tree at
`3614c87`: 24 `PARAMS` declarations across the scenes and the engine stages, and 33 per-parameter
tables in the roster, of which 21 carry a default column. The coverage is real and it is partial by
construction, because every row was written by hand in response to a question someone once had.

The existing guard proves the wrong property for a reference. It asserts that each declared name
appears in backticks *somewhere* in the file — satisfied by the one-row table — and so it cannot
notice that a parameter's default changed, that its documented range no longer reads, or that a
parameter is named and never explained. The three copies of each name (the `PARAMS` list, the
`set_param` match, the README) are held to each other; the *meaning* is held to nothing.

The user's decision at interview was that the per-system reference — name, default, range,
one-line meaning, for every parameter — is generated from the engine rather than written by hand.

## Decision

**Each scene and each engine stage declares its parameters as a `ParamSpec` — name, default, the
range that reads, and a one-line doc — in place of the bare `&[&str]` list it declares today, and a
generated block in `presets/README.md` renders one table per system from those declarations.**

The block sits between `<!-- params:begin -->` and `<!-- params:end -->` markers, replacing the
one-row-per-system table under `## Systems and their named parameters`. It is generated by a
`cargo` entry point in `core` (a test that rewrites the block when an environment variable asks it
to, and otherwise asserts the committed block matches what it would write — the same shape as
`scripts/toc.mjs --check`). A hand edit inside the markers fails the test; the essays below the
markers stay hand-written and are where depth lives. The site publishes the roster as it does today
and gains a per-system table by publishing the same file.

The shared blocks — the colour and framing names every scene delegates to `scenes::common`, the
engine-stage names in `background`, `bloom`, `feedback`, `ink`, `kaleidoscope`, `post`, `tonemap`,
`trails` — declare their specs once, and the generator composes a system's table from its own
specs plus the shared blocks it reaches, which is the same composition `set_param` performs at
runtime. The **structural tables** (`[curve]`, `[generator]`, `[particles]`, `[spectrum]`) are
serde structs, not parameters, and stay hand-documented.

`every_declared_param_is_documented_in_the_presets_readme` is retired by this: a declared parameter
cannot be absent from a block generated from the declarations. What replaces it is the assertion
that every `ParamSpec` carries a non-empty doc line, which is the property the old test could not
state.

## Consequences

### Positive

- Every parameter of every system has a default and a meaning on one page, and it cannot be
  missing, because the page is derived from the code that reads it.
- A renamed, retired or re-defaulted parameter changes the roster in the same commit or fails the
  test. The Mode 4 sweep row *"any scene param added/renamed/re-defaulted"* becomes mechanical.
- The `preset-author` lane, which is pointed at this file instead of keeping its own catalogue
  ([ADR-0017](0017-preset-author-skill-lane.md)), gets the reference it has been reconstructing
  from essays.

### Negative

- **Roughly two hundred one-line docs have to be written, in Rust, once.** They are the cost of
  the decision and the plan phase budgets for them. The material exists in the essays; the work
  is condensing it, not researching it.
- **A doc line in Rust is a second place to say what a parameter does**, beside the essay. The
  rule is that the spec's line is the *definition* and the essay is the *discussion*; the plan's
  review checks that no essay contradicts its table.
- **`ParamSpec` widens what a scene declares.** The `Scene` trait itself does not change — the
  declarations are `const` items today and stay `const` items — but every scene file is touched,
  and Plans 0140 and 0092 edit scene files too. The plan runs in a worktree for that reason.
- A default declared in a `ParamSpec` and a default applied in `reset_params` are two copies of
  one number until the scene reads its default *from* the spec. The plan requires that read, so
  the table cannot state a default the engine does not apply.

### Neutral

- The block is markdown, so GitHub and an editor show the same tables the site does. Under
  [ADR-0166](0166-a-published-document-splits-into-routes-by-size.md) the section splits into one
  route per system if it grows past the section threshold, and stays one page if it does not;
  either is acceptable and neither is configured.

## Alternatives considered

### Alternative A — Restructure the roster by hand, one section per system

No engine change, and the existing name-only test as the only guard. Rejected because it repeats
the property that produced today's partial coverage: a hand-written default is a copy of a Rust
constant that nothing compares, and the roster already shows what that yields over fifteen plans —
21 default columns for 24 declarations, all written when someone asked.

### Alternative B — Generate the reference at site build time, from `cargo`

The Pages workflow would run a `cargo` entry point and the site would render its output, with no
generated block in the tree. Rejected because the roster is the `preset-author` lane's catalogue
and the lane reads the file, not the site; a reference that exists only in `site/dist/` is
invisible to the one reader ADR-0017 built the file for. The committed block serves both, and the
test holds it current.

### Alternative C — rustdoc is the reference

Publishing rustdoc (ADR-0169) and documenting each parameter on its `PARAMS` entry. Rejected
because a `&[&str]` has no per-element doc, a preset author is not a rustdoc reader, and the roster
would still be a second copy. rustdoc is the reference for the *crate*; the parameter surface is
read by people who never open Rust.

### Alternative D — Document parameters in the preset schema (`core/src/preset/schema/`)

The schema already lists `GLOBAL_PARAMS` and validates a binding's name at load. Declaring specs
there instead of beside each scene would centralise them and separate them from the code that
applies them, which is the drift the three-copies test was written against. The spec lives where
`set_param` lives.

## Outcome (2026-09-06, at [Plan 0156](../plans/done/0156-the-site-becomes-the-reference.md)'s close)

**The decision held and the one Consequence written as a guarantee was false when the plan shipped
it.** That bullet says the plan *"requires that read, so the table cannot state a default the engine
does not apply."* The read was required and it was not universal. `spectrum`'s `curve` reached the
generated block declaring `default: 0.0`, `range: [-1.0, 1.0]` and a bipolar bend over an engine
applying `DEFAULT_CURVE = 1.0` and `level.powf(curve.clamp(0.05, 4.0))` -
[ADR-0040](0040-spectrum-level-curve-applies-before-the-easing.md)'s exponent, where `1.0` is the identity. It was the
**only** `DEFAULT_*` constant in the tree that never adopted `default_of`, so the single-copy
property this ADR rests on simply did not reach it, and no render, golden or behavioural gate could
see the difference: the engine was right and only the published row was wrong.

**A guarantee that lives in a `const fn` needs a gate that says every declaration uses it.** The
repair is `a_parameter_default_is_declared_once`, a source scan over `core/src/render/` that finds
128 spec/constant pairs and passes a pair only when one side derives from the other. **Two literals
side by side is the finding whether or not they agree today** — `DEFAULT_ROTATION` in the same file
was the same shape, agreeing and therefore latent, and a value comparison could have stated neither.

The counts the Context measured at `3614c87` moved on delivery: 24 `PARAMS` declarations became
**26 rosters**, and the 33 hand-written tables became **19 generated ones** — 341 rows, 180 distinct
parameters — because the generator composes a system's table from its own specs plus the shared
blocks rather than from one table per hand-written section. The Neutral bullet on
[ADR-0166](0166-a-published-document-splits-into-routes-by-size.md) resolved to the split arm: the
block's `###` headings crossed the section threshold and the site now serves nineteen per-system
routes.
